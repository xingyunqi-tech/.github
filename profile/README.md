### 从哪里开始？

- **开发全栈 Web 应用**：从 [t3-app-temp](https://github.com/xingyunqi-tech/t3-app-temp) 了解项目结构和开发流程。
- **参考门户与后台实现**：浏览 [organova-website](https://github.com/xingyunqi-tech/organova-website) 的业务模块与部署说明。
- **开发小程序或多端应用**：查看 [uniapp-template](https://github.com/xingyunqi-tech/uniapp-template) 的平台支持、组件与 API 接入方式。
- **查看服务端模板**：进入 [nestjs-template](https://github.com/xingyunqi-tech/nestjs-template) 查看当前代码与分支。

## 技术方向

**全栈 Web**  
围绕 Next.js、React 与 TypeScript 构建应用，通过 tRPC、Zod 和 Drizzle 连接页面、接口与数据层。

**多端应用**  
围绕 Uni-app 与 Vue 3 组织跨平台开发，结合 Pinia 状态管理与基于 OpenAPI 的客户端代码生成，减少重复接入工作。

**工程质量与交付**  
在项目中积累代码检查、类型检查、单元测试、端到端测试和容器化部署实践。具体工具与执行要求以各仓库文档为准。

## 我们重视的工程实践

- **清晰的边界**：让页面、业务逻辑、接口与数据访问各有职责。
- **可复用的基础**：把通用结构沉淀为模板，把业务差异留在具体项目。
- **可验证的修改**：结合类型检查、代码检查与测试验证变更。
- **可接手的项目**：用文档说明环境配置、开发命令和部署流程。

## 交流与协作

欢迎围绕具体项目交流问题与实现思路。

- **问题反馈**：请在对应仓库的 Issues 中说明复现步骤、运行环境、预期结果与实际表现。
- **功能建议**：请描述使用场景、希望解决的问题及已有方案的限制。
- **代码贡献**：请先阅读目标仓库的说明与贡献约定，让 Pull Request 聚焦一个明确问题，并附上验证方式。

各仓库的使用和分发条件，请以其许可证及相关说明为准。
